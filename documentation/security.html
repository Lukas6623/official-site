MODULE 01 / SECURITY

Security

Защита Linux-сервера от SSH brute-force атак.

ServerGuard Security — модуль безопасности ServerGuard, предназначенный для автоматического обнаружения и ограничения массовых попыток подбора учётных данных через SSH.

Модуль работает непосредственно на Linux-сервере и функционирует в фоновом режиме. Управление и настройка выполняются через ServerGuard.

Основная задача Security:

обнаружить подозрительную серию неудачных попыток SSH-аутентификации и автоматически ограничить источник таких попыток.

1. Что защищает ServerGuard Security

SSH является одним из основных способов удалённого администрирования Linux-серверов.

Если сервер доступен из Интернета, злоумышленники могут автоматически отправлять большое количество попыток входа, например:

username: root
password: 123456

username: admin
password: password

username: ubuntu
password: qwerty

...

Такие атаки называются brute-force attacks.

ServerGuard Security предназначен для автоматического обнаружения подобных попыток.

Вместо того чтобы администратор самостоятельно просматривал журналы SSH, система постоянно анализирует события аутентификации и реагирует на подозрительную активность.

2. Как работает защита

Упрощённая схема:

              SSH
               |
               v
       Authentication
               |
               v
       System security logs
               |
               v
       ServerGuard Security
               |
               v
       Анализ попыток входа
               |
               v
        Определение источника
               |
               v
         Проверка правил
               |
               v
       Подсчёт неудачных
          попыток
               |
               v
       Порог превышен?
          /          \
        НЕТ           ДА
         |             |
         v             v
     Продолжить     Ограничить
                     источник

Таким образом, ServerGuard не пытается блокировать каждого пользователя после первой ошибки.

Система предназначена именно для обнаружения серий подозрительных попыток.

3. Почему одна неправильная попытка не считается атакой

Обычный пользователь может ошибиться при вводе пароля.

Например:

Попытка 1 → ошибка
Попытка 2 → ошибка
Попытка 3 → успешный вход

Сам факт наличия нескольких ошибок ещё не означает, что сервер атакуют.

Поэтому Security использует настраиваемый порог.

Например, если администратор установил:

5 неудачных попыток

система может рассматривать достижение этого количества как основание для автоматического ограничения источника.

Конкретные значения зависят от конфигурации сервера.

4. Контроль источника атак

Security связывает неудачные попытки авторизации с источником подключения.

Это позволяет обрабатывать разные адреса независимо.

Например:

IP A → 2 неудачные попытки
IP B → 1 неудачная попытка
IP C → 5 неудачных попыток

При достижении установленного порога действие применяется к соответствующему источнику.

Это позволяет не блокировать весь сервер из-за активности одного адреса.

5. Автоматическая блокировка

После достижения установленного порога ServerGuard может передать информацию механизму firewall Linux.

В результате источник атаки получает ограничение на дальнейшие подключения.

Упрощённо:

Подозрительная активность
          |
          v
Порог достигнут
          |
          v
Firewall
          |
          v
Источник заблокирован

Таким образом, ServerGuard не просто сообщает администратору:

«На сервер поступает много попыток входа».

Он может автоматически применить защитное действие.

6. Временная и постоянная блокировка

В зависимости от конфигурации администратора блокировка может иметь различный характер.

Временная блокировка

Источник ограничивается на определённый период.

После завершения периода ограничение может быть снято автоматически.

Схема:

Атака
  ↓
Обнаружение
  ↓
Блокировка
  ↓
Ожидание
  ↓
Разблокировка

Постоянная блокировка

Источник остаётся заблокированным до тех пор, пока администратор или система не выполнит соответствующее действие.

Выбор режима зависит от политики безопасности сервера.

7. Whitelist

ServerGuard поддерживает список доверенных источников.

Администратор может указать адреса, которые не должны попадать под автоматическую блокировку.

Это может быть полезно для:

  • административных сетей;
  • доверенных серверов;
  • систем мониторинга;
  • автоматизированных сервисов;
  • других известных источников подключений.

При настройке whitelist необходимо внимательно проверять добавляемые адреса.

Если в список доверенных случайно добавить нежелательный источник, автоматическая защита не сможет применить к нему обычное правило блокировки.

8. Работа в фоновом режиме

Security не требует постоянного открытия ServerGuard на компьютере пользователя.

После установки защитный компонент работает непосредственно на Linux-сервере как системный фоновый процесс.

Это означает:

Windows ServerGuard
        |
        | управление
        v
Linux Server
        |
        v
Security
        |
        v
работает самостоятельно

Windows-приложение используется для управления модулем, просмотра его состояния и выполнения административных операций.

Сам механизм обнаружения атак работает на сервере.

9. Работа после перезагрузки сервера

Security интегрируется с системным менеджером Linux.

Это позволяет запускать защитный компонент автоматически после перезагрузки сервера.

Общий процесс:

Linux Server Restart
        |
        v
System initialization
        |
        v
ServerGuard Security
        |
        v
Protection active

Поэтому администратору не требуется вручную запускать защитный скрипт после каждой перезагрузки.

10. Что происходит во время атаки

Рассмотрим условный пример.

Допустим, один источник начинает отправлять большое количество неудачных попыток SSH-аутентификации.

Система обнаруживает события:

Неудачная попытка
        ↓
Неудачная попытка
        ↓
Неудачная попытка
        ↓
...

Security отслеживает количество таких событий.

После достижения настроенного порога:

Threshold reached
        ↓
Security action
        ↓
Firewall restriction

Дальнейшие подключения с этого источника ограничиваются средствами firewall.

11. Что получает администратор

ServerGuard позволяет администратору контролировать состояние защитного механизма.

В зависимости от версии ServerGuard могут быть доступны:

  • состояние Security;
  • состояние системного сервиса;
  • информация о событиях;
  • настройки защиты;
  • список заблокированных адресов;
  • статистика;
  • управление блокировками;
  • обновление защитного компонента.

Это позволяет выполнять основные операции через ServerGuard вместо ручного управления отдельными Linux-командами.

13. Почему защита работает на Linux, а не только в Windows

ServerGuard является инструментом управления Linux-серверами.

Поэтому обнаружение атак выполняется непосредственно на защищаемом сервере.

Это имеет важное преимущество:

Windows компьютер пользователя
        |
        | может быть выключен
        |
        X

При этом:

Linux Server
        |
        v
Security
        |
        v
продолжает работать

То есть работа защитного механизма не должна зависеть от того, открыт ли сейчас Windows-клиент.

14. Защита является многоуровневой

Security является только одним из компонентов ServerGuard.

Общая система может объединять несколько независимых механизмов:

                    ServerGuard
                         |
       +-----------------+-----------------+
       |                 |                 |
       v                 v                 v
   SSH Security      File Integrity     SSH Keys
       |                 |                 |
       v                 v                 v
 Brute-force         FileGuard        Key Guard
 protection
       |
       v
    Firewall

Это означает, что ServerGuard не должен рассматриваться как один механизм, который пытается решить все проблемы безопасности.

Каждый компонент выполняет свою задачу.

15. Security не является антивирусом

Важно правильно понимать назначение модуля.

Security предназначен прежде всего для защиты SSH от автоматизированных попыток подбора доступа.

Он не является:

  • полноценным антивирусом;
  • универсальным malware scanner;
  • полноценной SIEM;
  • полной системой IDS/IPS;
  • системой анализа всего сетевого трафика;
  • заменой firewall;
  • заменой резервного копирования;
  • заменой системного администратора.

Security решает более конкретную задачу:

обнаружение подозрительной активности при SSH-аутентификации и автоматическое ограничение источника.

16. Что Security не может гарантировать

Ни одна система защиты от brute-force не должна рассматриваться как абсолютная гарантия безопасности.

Например, Security не решает автоматически следующие проблемы:

  • украденный пароль;
  • украденный SSH-ключ;
  • уязвимость самого SSH-сервера;
  • уязвимое веб-приложение;
  • вредоносное программное обеспечение;
  • компрометацию учётной записи;
  • уязвимость операционной системы;
  • ошибки конфигурации;
  • социальную инженерию.

Поэтому Security является одним из уровней защиты, а не единственной защитой сервера.

17. Почему ServerGuard использует несколько механизмов

Безопасность сервера нельзя строить вокруг одного правила.

Например:

SSH protection
       +
Firewall
       +
SSH hardening
       +
SSH Key monitoring
       +
File integrity monitoring
       +
Security monitoring

дают более комплексный контроль.

Если одна технология отвечает за обнаружение определённого типа событий, другая может отвечать за ограничение последствий.

Именно поэтому ServerGuard состоит из отдельных специализированных модулей.

18. Что происходит с данными

Security использует служебные данные для хранения информации о своей работе.

Эти данные могут использоваться для:

  • текущего состояния защиты;
  • счётчиков;
  • статистики;
  • истории событий;
  • информации о блокировках;
  • настроек модуля.

Рабочие данные находятся на Linux-сервере.

Это позволяет защитному компоненту продолжать работу независимо от Windows-интерфейса.

19. Обновление Security

ServerGuard поддерживает обновление защитного компонента.

При обновлении система должна сначала подготовить новую версию, выполнить необходимые проверки и только после этого заменить рабочий компонент.

Также предусматривается резервирование предыдущей версии.

Общий принцип:

Текущая версия
       |
       +----> Backup
       |
       v
Новая версия
       |
       v
Проверка
       |
       v
Установка
       |
       v
Перезапуск защиты
       |
       v
Проверка состояния

Такой подход уменьшает вероятность того, что повреждённый или некорректный файл сразу заменит работающий компонент.

20. Автоматическое восстановление работы

Защитный компонент запускается как системная служба Linux.

Системный менеджер может контролировать состояние процесса и повторно запускать его после неожиданного завершения, если это предусмотрено конфигурацией сервера.

Это повышает устойчивость защиты к отдельным сбоям процесса.

21. Безопасность самого ServerGuard

ServerGuard использует повышенные системные права для выполнения некоторых защитных операций.

Это необходимо, поскольку управление системным firewall и некоторыми системными службами требует административных полномочий.

Поэтому важно:

  • использовать ServerGuard только на серверах, которыми вы управляете;
  • защищать учётные данные администратора;
  • использовать сильную аутентификацию;
  • не передавать доступ к серверу неизвестным пользователям;
  • регулярно обновлять операционную систему;
  • контролировать установленные компоненты.

ServerGuard является инструментом администрирования и безопасности, поэтому его необходимо использовать с соответствующими административными правами и ответственностью.

22. Может ли злоумышленник обойти защиту, зная, как она работает?

Знание принципа работы системы само по себе не должно считаться механизмом, от которого зависит безопасность.

ServerGuard не должен рассчитывать на то, что атакующий:

«не знает, что на сервере установлен Security».

Например, пользователь может знать, что ServerGuard контролирует SSH-аутентификацию.

Это не отменяет сам механизм:

Атакующий знает о защите
        |
        v
Пытается атаковать SSH
        |
        v
Security получает событие
        |
        v
Анализ
        |
        v
Защитное действие

Поэтому публичная документация ServerGuard может открыто объяснять назначение и принцип работы модулей.

При этом внутренние детали реализации, которые не нужны пользователю, не обязательно публиковать.

23. Что пользователь должен знать

Пользователю важно понимать:

ServerGuard Security:

  • контролирует SSH-аутентификацию;
  • обнаруживает большое количество неудачных попыток;
  • связывает события с источниками подключений;
  • учитывает настроенные исключения;
  • может автоматически применять firewall-блокировку;
  • поддерживает различные режимы блокировки;
  • работает на самом Linux-сервере;
  • запускается как системный компонент;
  • может работать независимо от открытого Windows-клиента;
  • является частью многоуровневой защиты ServerGuard.

27. Пример для обычного пользователя

Представим, что сервер находится в Интернете.

Неизвестный источник начинает отправлять большое количество запросов на SSH.

Без автоматизированной защиты администратору пришлось бы самостоятельно отслеживать журнал и принимать решение о блокировке.

С ServerGuard процесс автоматизируется:

Попытки входа
      ↓
Обнаружение активности
      ↓
Подсчёт
      ↓
Срабатывание правила
      ↓
Firewall restriction
      ↓
Источник ограничен

При этом администратор может продолжать работать с сервером через разрешённый источник.

28. Почему ServerGuard не просто блокирует SSH полностью

Полное отключение SSH не всегда возможно.

SSH используется администраторами для:

  • удалённого управления;
  • обслуживания сервера;
  • обновления программного обеспечения;
  • диагностики;
  • резервного администрирования.

Поэтому задача Security заключается не в том, чтобы просто отключить SSH.

Задача состоит в том, чтобы сохранить возможность администрирования и одновременно автоматически реагировать на подозрительную активность.

29. Рекомендации по безопасному использованию

Для повышения общей безопасности сервера рекомендуется использовать Security совместно с другими средствами защиты.

В частности:

  • использовать сильные пароли;
  • по возможности применять SSH-ключи;
  • отключать ненужные способы аутентификации;
  • регулярно обновлять Linux;
  • ограничивать административный доступ;
  • использовать firewall;
  • контролировать SSH-конфигурацию;
  • контролировать SSH-ключи;
  • использовать FileGuard или другие средства контроля целостности;
  • регулярно проверять журналы безопасности;
  • создавать резервные копии важных данных.

ServerGuard предназначен для того, чтобы объединить часть этих задач в единой системе управления.

30. Ограничения

Security специально ориентирован на SSH brute-force.

Поэтому его нельзя рассматривать как защиту от всех возможных атак.

Например, если злоумышленник уже получил действующие учётные данные, само наличие brute-force protection не означает, что его доступ автоматически будет заблокирован.

По этой причине безопасность сервера должна строиться на нескольких уровнях.

33. Важное замечание

ServerGuard Security является одним из уровней защиты, а не гарантией абсолютной безопасности.

Ни одна система автоматической блокировки не способна устранить все возможные угрозы.

Безопасность сервера зависит также от:

  • конфигурации SSH;
  • качества паролей и ключей;
  • состояния операционной системы;
  • установленных приложений;
  • сетевой конфигурации;
  • прав пользователей;
  • своевременности обновлений;
  • других средств защиты.

ServerGuard предназначен для того, чтобы автоматизировать обнаружение и реакцию на определённый класс угроз и объединить эту защиту с другими механизмами безопасности.

35. Итог

ServerGuard Security предназначен для автоматизации одной из распространённых задач Linux-администрирования — защиты SSH от массовых попыток подбора доступа.

Вместо ручного постоянного просмотра журналов система:

  1. получает информацию о событиях SSH;
  2. анализирует попытки аутентификации;
  3. отслеживает активность источников;
  4. применяет заданные правила;
  5. при необходимости передаёт решение firewall;
  6. ограничивает подозрительный источник;
  7. продолжает работать в фоновом режиме.

Security при этом является только одним из компонентов ServerGuard.

Вместе с FileGuard, SSH Key Guard, SSH Hardening, мониторингом и другими модулями он образует многоуровневую систему защиты и управления Linux-сервером.

не просто сообщить администратору о проблеме, а автоматизировать обнаружение и реакцию на определённые типы угроз, сохраняя при этом возможность контроля со стороны администратора.
