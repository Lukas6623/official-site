GUIDE / SSH KEY SETUP

SSH Key Setup

Complete guide for creating an SSH key, configuring Linux authentication and connecting ServerGuard securely.

1. Overview

ServerGuard supports SSH authentication using an SSH private key. This allows you to connect to a Linux server without entering the account password during every connection.

SSH key authentication is also used by ServerGuard as a safety mechanism when applying SSH Hardening.

2. Requirements

  • Windows 10 or Windows 11.
  • OpenSSH client.
  • A Linux server with SSH access.
  • A user account with SSH access.
  • Permission to modify the user's SSH configuration.

3. Check OpenSSH on Windows

Open PowerShell and run: 

ssh -V

If OpenSSH is installed, Windows will display the installed OpenSSH version.

4. Generate an SSH key

The recommended key type for ServerGuard is Ed25519. 

ssh-keygen -t ed25519 -C "ServerGuard"

When Windows asks where to save the key, press Enter to use the default location: 

C:\Users\YOUR_USERNAME\.ssh\id_ed25519

You can also protect the private key with a passphrase. This is recommended for important servers.

5. Private key and public key

Two files are created:

File Purpose
id_ed25519 Private key. Never share this file.
id_ed25519.pub Public key. This key is installed on the server.

Never upload your private key to GitHub, Telegram, email or any public service.

6. Install the public key on Linux

First display your public key: 

Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"

Copy the complete line beginning with: 

ssh-ed25519

On the Linux server create the SSH directory: 

mkdir -p ~/.ssh
chmod 700 ~/.ssh

Open the authorized keys file: 

nano ~/.ssh/authorized_keys

Paste your public key into the file and save it. Then set the correct permissions: 

chmod 600 ~/.ssh/authorized_keys

7. Test SSH key authentication

From Windows PowerShell: 

ssh -i "$env:USERPROFILE\.ssh\id_ed25519" USER@SERVER_IP

Replace USER with the Linux username and SERVER_IP with the server address.

If everything is configured correctly, SSH will authenticate using the private key.

8. Test password authentication separately

You can test password authentication without deleting or modifying your SSH keys: 

ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password USER@SERVER_IP

This command temporarily disables public-key authentication for this connection only.

9. Configure ServerGuard

Start ServerGuard and open the server connection settings.

Field Value
Host Linux server IP address or hostname
Port Usually 22
Username Linux account username
Authentication Private key
Private key id_ed25519
Key passphrase Enter it if the private key is protected

Select the private key file: 

C:\Users\YOUR_USERNAME\.ssh\id_ed25519

Do not select id_ed25519.pub. The .pub file is the public key and is not used as the private authentication key.

10. Authentication verification

When ServerGuard connects using the private key, the connection should report successful public-key authentication. 

Auth: Private key

Authenticating (Private key)...

Authenticated successfully.

This confirms that ServerGuard successfully authenticated using the SSH private key.

11. SSH Hardening safety mechanism

ServerGuard uses the current authentication method as an additional safety check before applying SSH Hardening.

If ServerGuard is connected using an SSH private key, hardening can continue.

If ServerGuard is connected using password authentication, hardening is blocked. 

Password authentication
        |
        v
SSH Hardening blocked
        |
        v
Password authentication remains enabled

This prevents ServerGuard from disabling password authentication while the current session depends on it.

To use SSH Hardening safely, connect ServerGuard using an SSH private key first.

12. SSH key fingerprint

A fingerprint is a short identifier of an SSH public key. It can be used to verify that the correct key is installed.

On Windows: 

ssh-keygen -lf "$env:USERPROFILE\.ssh\id_ed25519.pub"

The output contains a fingerprint similar to: 

256 SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx ServerGuard

13. Using a passphrase

An SSH private key can be protected with a passphrase. If the private key is stolen, the passphrase provides an additional layer of protection.

When ServerGuard asks for: 

Key passphrase:

enter the passphrase used when the key was created.

14. Troubleshooting

Permission denied (publickey)

Check that the public key is present in: 

~/.ssh/authorized_keys

Also verify permissions: 

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

Wrong private key selected

ServerGuard must use the private key: 

id_ed25519

not: 

id_ed25519.pub

Wrong username

The public key must be installed in the home directory of the account that you are connecting as.

Key works in terminal but not in ServerGuard

Check the key path and make sure ServerGuard is using the same private key that was tested with the OpenSSH client.

15. Security recommendations

  • Never share your private key.
  • Use a passphrase for important servers.
  • Keep private keys outside public repositories.
  • Do not send private keys through Telegram or email.
  • Use different keys for different environments when appropriate.
  • Regularly review authorized_keys.
  • Use SSH Key Guard to monitor changes to SSH keys.

16. Complete authentication flow

Windows
   |
   | id_ed25519
   v
ServerGuard
   |
   | SSH public-key authentication
   v
Linux SSH server
   |
   | authorized_keys
   v
Authenticated session
   |
   v
ServerGuard modules
   |
   +-- Security
   +-- SSH Hardening
   +-- SSH Key Guard
   +-- FileGuard
   +-- Telegram Bot

17. Summary

SSH key authentication provides ServerGuard with a secure way to connect to Linux servers without relying on a password for every connection.

The recommended workflow is:

  1. Generate an Ed25519 SSH key.
  2. Install the public key on the Linux server.
  3. Test SSH authentication from Windows.
  4. Configure ServerGuard to use the private key.
  5. Verify successful authentication.
  6. Use SSH Hardening only after key authentication works.
