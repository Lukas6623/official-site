MODULE 04 / SSH KEY GUARD

SSH Key Guard

Мониторинг SSH-ключей пользователей Linux-сервера.

SSH Key Guard — компонент ServerGuard, который следит за SSH-ключами пользователей Linux-сервера. Он обнаруживает добавление и удаление ключей в authorized_keys и сохраняет подробное событие.
Версия модуля 1.0.1
Платформа Linux
Язык Python 3
Основной объект ~/.ssh/authorized_keys

1. Зачем нужен SSH Key Guard

Файл authorized_keys определяет, какие публичные ключи могут входить на сервер под конкретным пользователем:

/home/<user>/.ssh/authorized_keys
/root/.ssh/authorized_keys

Если в него без вашего ведома добавлен чужой ключ, это скрытый способ входа: он продолжит работать даже после смены пароля. SSH Key Guard позволяет быстро заметить такое изменение.

обнаружить изменение → определить ключ → записать событие

2. Основные возможности

  • мониторинг authorized_keys всех пользователей;
  • обнаружение добавленных и удалённых ключей;
  • baseline — эталонный набор ключей;
  • fingerprint SHA256:... для удобной идентификации ключа;
  • интеграция с Linux Audit (auditd): процесс, пользователь, команда;
  • сетевая информация и GeoIP для публичных IP;
  • структурированные JSON-события и локальная история;
  • работа как служба systemd;
  • простой командный интерфейс.

3. Как это работает

Модуль сочетает два механизма:

Snapshot-мониторинг   — что изменилось?
Linux Audit           — какая операция и какой процесс это сделали?

authorized_keys
       |
       v
   snapshot
       |
       v
  сравнение с предыдущим состоянием
       |
  +----+-----------+
  |                |
  v                v
key_added      key_removed
  |                |
  +-------+--------+
          |
          v
   создание события
          |
          v
    JSON-журнал

4. Baseline

Перед мониторингом создаётся baseline — список ключей, которые считаются известными.

baseline:   KEY-A, KEY-B
позже:      KEY-A, KEY-B, KEY-C
результат:  KEY-C → новый ключ (key_added)

Создать baseline вручную:

python3 ssh_key_guard.py init

5. События

Событие Значение
key_added Обнаружен новый SSH-ключ
key_removed Ранее известный ключ больше не найден

Пример: было KEY-A, стало KEY-A, KEY-B — создаётся key_added для KEY-B.

6. Что сохраняется о ключе

{
  "type": "ssh-ed25519",
  "fingerprint": "SHA256:...",
  "comment": "admin@computer",
  "line": 3
}

Поддерживаются распространённые типы: ssh-rsa, ssh-ed25519, ecdsa-sha2-nistp256/384/521, а также security-key и сертификатные варианты OpenSSH.

Fingerprint позволяет идентифицировать ключ, не показывая его целиком.

7. Информация о пользователе и файле

Событие связывается с аккаунтом, чей authorized_keys был изменён:

{ "username": "admin", "uid": 1000, "home": "/home/admin", "shell": "/bin/bash" }

Также сохраняются путь к файлу и его метаданные (размер, права, время изменения, SHA-256).

8. Linux Audit

Если на сервере установлен auditd, SSH Key Guard получает дополнительный контекст операции:

UID, AUID, PID, PPID
имя процесса и исполняемый файл
команда и рабочий каталог
результат операции, терминал

Например: ключ добавлен процессом vim пользователя с UID 1000, либо скриптом python3.

AUID сохраняет исходного пользователя даже после sudo или su — это помогает понять, кто именно выполнил действие.

sshd → bash → sudo → vim

9. Работа без auditd

Без auditd модуль продолжает обнаруживать изменения по сравнению snapshot-ов: какой ключ добавлен или удалён и какой пользователь затронут. Не будет только подробностей о процессе и операции, поэтому для полной картины auditd рекомендуется.

10. Сетевая информация и GeoIP

Модуль может определить IP-адрес, связанный с SSH-сессией (из audit или активной сессии).

Для публичных IP используется внешний сервис ipinfo.io: страна, регион, город, организация, hostname. Для локальных и приватных адресов запрос не выполняется.

GeoIP не определяет физическое местоположение человека. Используйте его как дополнительную подсказку. Учтите, что публичный IP передаётся стороннему сервису.

11. Хранение данных

  • Events — журнал ssh_key_events.json, до 5000 последних событий;
  • State — текущее известное состояние для сравнения.

Запись выполняется через временный файл с последующей заменой, поэтому аварийное завершение не должно повредить журнал.

Каждое событие имеет уникальный ID:

{
  "id": "...", "version": "1.0.1", "timestamp": "...",
  "action": "key_added",
  "account": {}, "file": {}, "key": {}, "old_key": null,
  "modifier": {}, "network": {}, "server": {}
}

12. Запуск и интервал проверки

По умолчанию проверка выполняется каждые 5 секунд:

python3 ssh_key_guard.py monitor

Другой интервал:

python3 ssh_key_guard.py monitor --interval 10

Для постоянной работы модуль запускается как служба systemd и после перезагрузки сервера стартует автоматически.

13. Команды

Команда Назначение
monitor Постоянный мониторинг
monitor --interval N Мониторинг с интервалом N секунд
init Создание baseline
scan Однократное сканирование
events Последние события
events N Последние N событий
audit Проверка Linux Audit
audit-remove Удаление audit-правил ServerGuard
version Версия модуля

14. Служба systemd

systemctl status serverguard-ssh-key.service
systemctl start serverguard-ssh-key.service
systemctl stop serverguard-ssh-key.service
systemctl restart serverguard-ssh-key.service

Журнал службы:

journalctl -u serverguard-ssh-key.service -n 50
journalctl -u serverguard-ssh-key.service -f

15. Требования и права

Нужны Linux, Python 3 и OpenSSH. Для расширенного аудита рекомендуются auditd, auditctl, ausearch; для сетевой информации используются ss и curl.

Часть функций требует прав администратора: чтение файлов других пользователей, работа с auditd, анализ процессов. Поэтому постоянный мониторинг обычно запускают от root.

16. Конфиденциальность

События могут содержать имя пользователя, UID, путь к authorized_keys, fingerprint, IP-адрес, команду и информацию о процессе. Это чувствительные данные: ограничьте доступ к журналам и файлам состояния только доверенными администраторами.

17. Что SSH Key Guard не делает

Это система мониторинга, обнаружения, аудита и логирования. Она не:

  • удаляет подозрительные ключи;
  • блокирует IP-адреса;
  • удаляет пользователей и меняет пароли;
  • останавливает SSH-сервер;
  • заменяет firewall и защиту от brute-force.

Решение о дальнейших действиях принимает администратор или другие компоненты безопасности.

SSH Key Guard Firewall Brute-force защита
Что контролирует Ключи в authorized_keys Соединения, порты, IP Неудачные попытки входа

18. Ограничения

  • Модуль анализирует распознанные SSH-ключи, поэтому изменение только комментария не всегда создаёт событие.
  • Проверка периодическая: изменение, которое вернули обратно между двумя проверками, может не попасть в snapshot. auditd снижает этот риск.
  • Недоступность GeoIP или другого дополнительного источника не останавливает основной мониторинг.

19. Рекомендации

  • создавайте baseline на заведомо «чистом» сервере;
  • устанавливайте и используйте auditd;
  • не изменяйте файлы состояния вручную;
  • ограничьте доступ к журналам;
  • следите за состоянием службы systemd;
  • регулярно разбирайте события и проверяйте незнакомые ключи;
  • используйте SSH Key Guard вместе с SSH Hardening, Security и FileGuard.

20. Итог

определяет пользователей → находит authorized_keys → создаёт baseline
→ сравнивает snapshot-ы → обнаруживает добавленные и удалённые ключи
→ добавляет контекст из auditd → сохраняет структурированное событие

SSH Key Guard отвечает за отдельный уровень безопасности — контроль SSH-ключей и связанных с ними событий.
